# Google Apps Scriptによる回答収集のセットアップ

## 1. 保存先を用意する

1. Googleスプレッドシートを新規作成します。共有範囲は管理者だけにしてください。
2. URLの `/d/` と `/edit` の間の文字列を控えます。これがスプレッドシートIDです。
3. 「拡張機能 → Apps Script」でプロジェクトを開き、`gas/Code.gs` の内容を貼り付けます。
4. 「プロジェクトの設定 → スクリプト プロパティ」に `SPREADSHEET_ID` を追加し、2のIDを設定します。
5. `setup` 関数を実行し、自分のスプレッドシートへの権限を許可します。`events` シートと列見出しが作成されます。既存データは削除しません。

## 2. Webアプリとして公開する

「デプロイ → 新しいデプロイ → 種類：ウェブアプリ」で次を選択します。

- 実行するユーザー：自分
- アクセスできるユーザー：全員（ログイン不要でアクセスできる設定）

組織アカウントのポリシーで「全員」を選べない場合、そのアカウントでは匿名収集を有効にできません。管理者の方針に沿うアカウント・公開方法を確認してください。スプレッドシート自体を一般公開する必要はありません。

発行された `https://script.google.com/macros/s/…/exec` を使用します。編集者向けの `/dev` URLは使用しません。コード更新時は「デプロイを管理 → 編集 → 新しいバージョン」で反映します。

## 3. アプリへURLを設定する

ローカルでは `.env.example` を `.env.local` にコピーし、以下を設定して開発サーバーを再起動します。

```text
VITE_GAS_ENDPOINT=https://script.google.com/macros/s/発行されたID/exec
```

GitHubでは「Settings → Secrets and variables → Actions → Variables」に同名のリポジトリ変数 `VITE_GAS_ENDPOINT` を設定し、Actionsを再実行します。このURLは公開JavaScriptに含まれる送信先であり、秘密鍵ではありません。Googleの認証情報やスプレッドシートIDはフロントに置きません。

未設定なら送信をスキップし、診断は通常どおり動きます。属性入力は任意、同意は初期状態でオフです。再診断では同意をリセットします。

## 4. 実際の保存を確認する

本物のURLを設定した後に、以下を確認してください。現時点ではGASを外部デプロイしていないため、この確認は未実施です。

1. 同意なしで診断：シートに行が増えない。
2. 同意ありで診断：`diagnosis` が1行追加される。q1〜q16、4軸、タイプ、任意属性、おすすめ6件が入る。
3. 結果の公式リンクをクリック：`spot_click` が追加され、同じ `result_id` と該当 `clicked_spot_id` が入る。
4. 結果画面でクリック送信を停止：以後のクリックで行が増えない。
5. 通信失敗時の再送：同じ `event_id` は重複登録しない。
6. 年代「10歳未満」・同行者「その他」は0、回答しない項目は空欄となる。

フロントは `Content-Type: text/plain;charset=UTF-8` のJSON文字列を `fetch` でPOSTします。GASのリダイレクト・CORS制約に対応するため `mode: no-cors` を使用します。レスポンスは不透明で、ブラウザからバリデーション結果やシート保存成功を確定できません。画面は「送信をリクエスト」と表示し、保存確認はシートで行います。8秒で待機を打ち切っても、既に届いた処理が保存される可能性があります。再送には同じイベントIDを使用します。

## 5. 列と検証

- `received_at`：GASの受付日時（UTC）。分析時の受付順はこれを優先。
- `timestamp`：端末側のイベント日時（UTC）。端末時計の影響を受ける。
- `session_id`：ブラウザに保存するUUID。同じブラウザの利用を関連付ける仮名IDであり、完全に連結不能なデータではありません。
- `result_id`：1回の診断を識別。クリックとの関連付けに使用。
- `event_id`：各送信を識別。排他ロック内で重複確認する。
- `q1`〜`q16`：1〜5。5が「とてもそう思う」。各軸4問目は逆転。
- `axis1`〜`axis4`：[-1,+1]。GASでも回答から再計算して一致を確認。
- `type`：4軸の符号から再計算して一致を確認。中立は左側。
- `recommended_spot_ids`：上位3件＋追加3件の順。`|` 区切り。
- `clicked_spot_id`：クリック時のみ。表示した6件のいずれか。

必須項目、UUID、版番号、時刻形式、選択肢、数値範囲、スコアとタイプの整合、観光地IDを検証します。文字列は既定値だけを保存するため、任意の数式や自由記述をシートに書き込みません。氏名・メール・位置情報・IP・User-Agentは保存しません。

公開された送信先であり、入力検証は送信者の本人確認ではありません。異常な投稿量やGASの割当超過がないか運用時に確認してください。保存期間、管理者の問い合わせ先、分析結果の公開範囲は公開前に決定してください。

## 仕様変更時

質問順、逆転項目、属性、タイプ、地点数、アプリ版を変更する場合はGASの検証も同期してください。`npm test` でフロントとの一致を検証できます。シートの列を変更する場合は新しいシート名を使うなど、既存回答の列ずれを避けてください。既存ヘッダーと異なると保存を拒否します。

参照：[Google公式 Web Apps](https://developers.google.com/apps-script/guides/web)、[Content Service](https://developers.google.com/apps-script/guides/content)。
